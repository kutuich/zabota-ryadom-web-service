# Production Checklist

- [ ] HTTPS включён.
- [ ] Caddy слушает внешние TCP 80 и 443.
- [ ] `zabota-web` опубликован только на `127.0.0.1:4000`.
- [ ] Домен открывает landing на `/`.
- [ ] `/app` открывает приложение.
- [ ] `/api/health` отдаёт JSON.
- [ ] `/legal/privacy` открывается.
- [ ] Старые PHP paths возвращают 404.
- [ ] `DATABASE_URL` указывает на persistent volume: `file:/data/zabota.db`.
- [ ] Uploads находятся на persistent volume `/opt/zabota/data/uploads` через `UPLOADS_DIR=/data/uploads`.
- [ ] `JWT_SECRET` заменён на production secret.
- [ ] `PAYMENT_PROVIDER=mock`.
- [ ] `SEED_DEMO_DATA=false`.
- [ ] `PRODUCTION_ADMIN_EMAIL`, `PRODUCTION_ADMIN_PASSWORD`, `PRODUCTION_ADMIN_PHONE` заданы перед первым запуском.
- [ ] T-Bank выключен.
- [ ] Начальный пароль администратора нужно заменить после первого входа.
- [ ] Есть backup перед обновлениями.
- [ ] Проверена регистрация заказчика.
- [ ] Проверена регистрация помощника.
- [ ] Проверен mock payment.
- [ ] Проверена админка платежей.
- [ ] Ручная корректировка создаёт отдельную операцию баланса и запись audit log.
- [ ] Списание основного и бонусного баланса не допускает отрицательного остатка.
- [ ] Manager видит операции баланса только для чтения и не видит форму корректировки.
- [ ] Перед реальной оплатой сделан backup `.env.production` и `/opt/zabota/data/zabota.db`.
- [ ] Тестовый терминал Т-Банка и HTTPS notification URL проверены.
- [ ] Подписанный `CONFIRMED` webhook зачисляет баланс ровно один раз.
- [ ] Повторный webhook не создаёт вторую операцию `payment_credit:<paymentId>`.
- [ ] При задержке webhook ручной `GetState` подтверждает pending-платёж.
- [ ] Повторный `GetState` и любой порядок webhook/GetState не удваивают баланс.
- [ ] Manager видит платежи read-only и не может вызвать refresh-status.
- [ ] `PAYMENT_RECEIPT_ENABLED=false` до отдельной проверки фискализации.
- [ ] В админке доступен раздел «Финансы → Мой налог» только для admin/superadmin.
- [ ] Только успешный платёж T-Bank появляется в реестре как ожидающий отражения; mock и внутренние операции отсутствуют в реестре и итогах.
- [ ] Реальный возврат через T-Bank или «Возврат по банку» появляется отдельной отрицательной операцией со статусом «Требует проверки».
- [ ] Для «Возврата по банку» проверены фактическая дата, банковский референс, списание только основного баланса и audit `admin.bank_refund.create`.
- [ ] Владелец вручную формирует, корректирует или аннулирует чек в приложении «Мой налог» и сохраняет контрольный статус.
- [ ] Подтверждено, что внутренний реестр не отправляет данные в ФНС автоматически.
