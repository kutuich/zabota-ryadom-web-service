## Agreement header

- request id и public number;
- идентификаторы Заказчика и Помощника;
- `AgreementVersion.id`, version, status и `termsHash`;
- snapshot выбранных задач и состояния Подопечного;
- комментарий условий;
- сумма помощи за визит и за весь график;
- даты подтверждения обеих сторон и финализации.

Оплата помощи проходит напрямую между сторонами. Документ не должен описывать выплату Помощнику сервисом или удержание сбора из оплаты помощи.

## Concrete expanded visits

Для каждого `RequestVisit`:

- sequence и локальная дата;
- start/end time, duration и timezone;
- tasks snapshot;
- индивидуальная согласованная сумма помощи и pricing breakdown этого визита;
- сервисный сбор каждой стороны;
- технический статус.

Несколько слотов одной даты являются отдельными визитами.

## Сервисные условия

- 50 ₽ с Заказчика и 50 ₽ с Помощника за визит;
- visit count и totals за конечный график;
- batch id и idempotency key;
- timestamps подтверждений.

Funding breakdown (`mainBalanceAmount`, `bonusBalanceAmount`, ledger ids) является внутренней admin-информацией и не включается в документ сторон без отдельного решения.

## Приватность

До `in_work` документ/DTO Помощника не содержит точный закрытый адрес, телефон, квартиру, подъезд, этаж, домофон или private comment. Формат печати/экспорта не должен ослаблять API policy.

## Ограничения

- Текст соглашения требует юридической проверки.
- Изменение финализированного графика с дельтой не поддержано.
- Спор и возврат сервисного сбора описываются только после отдельного юридического решения.
- Печать технически необязательна; этот draft не определяет доказательственную силу.
