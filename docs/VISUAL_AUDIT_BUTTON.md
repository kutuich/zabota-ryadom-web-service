# Кнопка визуального аудита «Забота Рядом»

Визуальный аудит проверяет только локальную версию `http://localhost:4000`. Публичный сайт и production-данные не проверяются и не изменяются.

## Как запустить

1. Дважды нажмите `start-zabota-local.command`.
2. Дождитесь открытия `http://localhost:4000`.
3. Проверьте в браузере:
   - `http://localhost:4000/app/audit/client`;
   - `http://localhost:4000/app/audit/performer`;
   - `http://localhost:4000/app/audit/admin`.
4. Дважды нажмите `audit-zabota-visual.command`.
5. Дождитесь строки «Визуальный аудит завершён».
6. Откройте новую папку в `../audits/visual`.
7. Заархивируйте папку `screenshots` как `screenshots.zip` и отправьте её вместе с `visual-audit-report.md` на проверку.

Если localhost не запущен, аудит не переходит к публичному сайту. Он создаёт отчёт с причиной ошибки и выводит:

```text
Локальный сайт не запущен.
Для визуального аудита сначала запустите start-zabota-local.command.
```

Если Playwright или Chromium не установлены, выполните из папки `web-service`:

```bash
npm install
npx playwright install chromium
```

## Локальные audit routes

`start-zabota-local.command` всегда передаёт в локальную Vite-сборку:

```text
VITE_ENABLE_VISUAL_AUDIT_ROUTES=true
```

Флаг попадает в frontend на этапе Docker build. Обычная production-сборка не передаёт этот build-arg; безопасное значение Dockerfile остаётся `false`.

Кабинеты работают на frontend mock-данных. Для этих URL AuthProvider не монтируется, API-клиент не вызывается, кнопки не отправляют данные.

## Где искать результаты

Каждый запуск создаёт отдельную папку:

```text
../audits/visual/visual-audit-ГГГГ-ММ-ДД-ЧЧММСС/
```

Внутри:

- `screenshots/` — PNG-скриншоты desktop, laptop и mobile;
- `visual-audit-report.md` — итог, найденные проблемы, список проверенных страниц и технический журнал.

## Что проверяется

Локальные публичные страницы:

- `/`;
- `/app`;
- `/prices.html`;
- `/security.html`;
- `/contacts.html`;
- `/how-it-works.html`;
- `/legal.html`.

Локальные mock-кабинеты:

- `/app/audit/client`;
- `/app/audit/performer`;
- `/app/audit/admin`.

Каждая страница проверяется в размерах `1440×900`, `1280×800` и `390×844`. Для `/app` отдельно проверяются вход, регистрация Заказчика и регистрация Помощника.

Аудит проверяет HTTP-ответ, горизонтальную прокрутку, выход элементов за экран, узкие кнопки и поля, обрезанный текст, битые изображения и тексты ошибок. В формах регистрации дополнительно проверяются поле города, документы, согласия и кнопка создания аккаунта.

## Безопасность

Аудит только открывает локальные страницы, читает DOM и сохраняет файлы отчёта. Он не создаёт аккаунты, заявки, балансы, платежи или согласия и не обращается к публичному сайту.

## Что делать при критичных проблемах

1. Откройте соответствующий скриншот и строку в разделе «Критичные визуальные проблемы».
2. Проверьте проблему вручную в localhost на том же размере экрана.
3. Исправьте проблему в коде и повторите визуальный аудит.
